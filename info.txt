5.1 SEARCH FIX (the main task — search now actually shows results)
Problem: the old code used a plain case-insensitive substring test
(`text.toLowerCase().includes(q)`), so it failed for normal human input:
   - "New Delhi – Ambala Cantt – Kalka" typed with a normal hyphen "-" instead
     of the en-dash "–"  -> no result
   - multi-keyword input like "New Delhi Ambala" or "delhi kalka" -> no result
   - "wap7" (without dash) -> no result
   - zero feedback when nothing matched (the grid just looked empty)

Solution (applied to ALL 3 pages, identical helper functions):

    normText(s)    -> lower-cases, replaces every non letter/number with a
                      space (kills – — - / . , & etc.), trims.
    textMatches(text, q)
                 -> empty query matches everything
                 -> full normalized phrase must appear, OR
                 -> the query with spaces removed must appear (so "wap7" hits
                    "WAP-7"), OR
                 -> EVERY whitespace-separated word of the query must appear
                    (so "new delhi ambala" and "delhi kalka" both match)
    escapeHtml(s)  -> escapes user text before it is put into innerHTML

   Where the code lives now:
   index.html            : normText / textMatches / escapeHtml,
                           renderPopup() , filterGamesGrid() , searchResults[]
   msts-routes.html      : normText / textMatches / escapeHtml,
                           renderRoutes() , filterRoutes() , updateStatus()
   msts-locomotives.html : normText / textMatches / escapeHtml,
                           renderLocos() , filterLocos() , updateStatus()

   Behaviour added / fixed:
   * routes page  : searching "KHANDESH DHULE UPDATE", "khandesh", "dhule",
     "delhi - kalka", "kalka", "toy train", "1,500+ km", "NR" etc. all
     show matching cards.
   * locos page   : "WAP-7", "wap7", "wap 7", "WAP" (3 results), "high speed
     passenger", "emd", "GZB" etc. all work.
   * NEW result status bar (#searchStatus) under the filter chips on BOTH
     listing pages: "Showing 2 of 6 routes for 'kalka'" + a Reset button,
     and a real empty state "No routes found for '...' [Clear search & filters]"
     (before: no message at all, page looked broken).
   * Zone / power-type chip can no longer hide your search results: if a search
     matches nothing inside the active chip, the code auto-switches the chip to
     "All Zones"/"All Power", re-runs, and shows a yellow note
     "...filter was ignored so your results could show."
   * Escape key clears the search box on the listing pages.
   * ?q= deep links still work (and now also scroll the control bar into view):
